Module 1: Overview & Architecture

Declarative Custom Resources vs CLI spark-submit in Kubernetes.

💡 Learning Objective

Deploy the Kubeflow Spark Operator onto a local Minikube cluster using Helm. Understand how Custom Resource Definitions (CRDs) enable GitOps and declarative `SparkApplication` workload management, replace long imperative `spark-submit` CLI calls, and provide automated pod lifecycle management and garbage collection.

Spark Operator Architectural Workflow

  • Review Declarative Operator Architecture Understand how CRDs, mutating webhooks, and controllers automate Spark pod scheduling.

Module 3: Deploy Spark Operator via Helm

Installing the Kubeflow Spark Operator Helm chart and mutating webhook.

1. Add Spark Operator Helm Repository

Helm CLI
helm repo add spark-operator https://kubeflow.github.io/spark-operator
helm repo update

2. Install the Chart into `spark-operator` Namespace

Helm CLI
helm install my-release spark-operator/spark-operator \
  --namespace spark-operator \
  --create-namespace \
  --set webhook.enable=true

3. Verify Operator Pod & Registered CRDs

Kubectl CLI
# Check operator controller pod status
kubectl get pods -n spark-operator

# Check registered CRDs
kubectl get crd | grep "spark"
  • Deploy Spark Operator Install Helm chart with mutating webhook enabled and verify operator pod and CRD registration.

Module 5: Deploy SparkApplication

Defining declarative custom resources for PySpark workloads.

SparkApplication Manifest (`manifests/spark-application.yaml`)

Kubernetes YAML
apiVersion: "sparkoperator.k8s.io/v1beta2"
kind: SparkApplication
metadata:
  name: spark-operator-demo
  namespace: default
spec:
  type: Python
  pythonVersion: "3"
  mode: cluster
  image: "spark-on-eks:latest"
  imagePullPolicy: IfNotPresent
  mainApplicationFile: "local:///opt/spark/work-dir/spark_app.py"
  arguments:
    - "local:///opt/spark/work-dir/sample_data.csv"
  sparkVersion: "3.5.1"
  restartPolicy:
    type: Never
  driver:
    cores: 1
    coreLimit: "1200m"
    memory: "512m"
    labels:
      version: 3.5.1
    serviceAccount: spark
  executor:
    cores: 1
    instances: 1
    memory: "512m"
    labels:
      version: 3.5.1

Submit Custom Resource

PowerShell
cd d:\trainings\aws_data_engineering\Lab7_spark_operator_minikube_lab
kubectl apply -f manifests/spark-application.yaml
Terminal
cd ~/trainings/aws_data_engineering/Lab7_spark_operator_minikube_lab
kubectl apply -f manifests/spark-application.yaml
  • Deploy SparkApplication Resource Apply `spark-application.yaml` manifest and initiate declarative Spark job scheduling.

Module 6: Monitor Job & View Logs

Tracking SparkApplication status, streaming driver logs, and teardown cleanup.

1. Query Custom Resource & Pod Status

Kubectl CLI
# Query SparkApplication status (SUBMITTED -> RUNNING -> COMPLETED)
kubectl get sparkapplications

# List operator-created pods
kubectl get pods

2. Stream Logs from Operator Driver Pod

Kubectl CLI
kubectl logs spark-operator-demo-driver -f

3. Cleanup Lifecycle

Kubectl & Helm CLI
# Delete custom resource (automatically deletes driver and executor pods!)
kubectl delete -f manifests/spark-application.yaml

# Uninstall Helm release and stop cluster
helm uninstall my-release -n spark-operator
minikube stop
  • Monitor & Cleanup Workload Track status transitions, stream driver logs, and verify automated garbage collection on resource deletion.
