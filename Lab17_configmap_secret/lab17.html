Module 1: Overview & Architecture

Inject ConfigMap via envFrom, map Secret via Volume Mount (`/etc/secrets`), and access secrets in PySpark code.

💡 Production Architecture Pattern
ConfigMaps are injected via envFrom to expose non-sensitive URLs and settings as environment variables. Sensitive credentials (passwords, access keys) are mapped securely via Volume Mounts (`/etc/secrets`). PySpark code reads these secret files directly from disk, preventing secret leakage in process environment trees.

Module Objectives

  • Master Minikube offline image loading: docker pull locally and minikube image load.
  • Create Secrets directly on CLI via kubectl create secret generic (no Secret YAML file).
  • Inject ConfigMap parameters into containers using envFrom.
  • Map Secrets into containers via volume mounts to /etc/secrets.
  • Author PySpark code that reads secret files directly from /etc/secrets/SNOWFLAKE_PASSWORD.
  • Orchestrate EMR on EKS Spark jobs via Airflow EmrContainerOperator.

Module 2: Minikube Offline Image Load Workflow

Pull container images locally using Docker CLI and load them directly into your local Minikube cluster cache.

⚠️ Minikube Network Restriction
When Minikube cannot download container images directly from Docker Hub due to network proxies, pull images locally with Docker CLI and push them to Minikube using minikube image load.
Bash / Zsh
# 1. Start Minikube cluster
minikube start --cpus 2 --memory 4096

# 2. Pull target container image locally via Docker CLI
docker pull nginx:alpine

# 3. Load container image into Minikube internal docker engine
minikube image load nginx:alpine

# 4. Verify image is present in minikube image cache
minikube image ls | grep "nginx"
PowerShell

# 2. Pull target container image locally via Docker CLI

# 3. Load container image into Minikube internal docker engine

3.2 Create Secret via kubectl create secret generic (No YAML File)

Bash / Zsh

Module 4: Pod Spec (ConfigMap via envFrom & Secret via Volume)

Inject ConfigMap via `envFrom` and map Secret via Volume Mount to `/etc/secrets`.

4.1 Pod Manifest (manifests/pod-with-configmap-secret.yaml)

YAML — pod-with-configmap-secret.yaml
apiVersion: v1
kind: Pod
metadata:
  name: demo-configmap-secret-pod
spec:
  containers:
    - name: demo-container
      image: nginx:alpine
      envFrom:
        - configMapRef:
            name: app-config
      volumeMounts:
        - name: secret-volume
          mountPath: /etc/secrets
          readOnly: true
  volumes:
    - name: secret-volume
      secret:
        secretName: app-secret

4.2 Verify Injection & Secret Files

Bash / Zsh
# 1. Apply pod manifest
kubectl apply -f manifests/pod-with-configmap-secret.yaml

# 2. Verify ConfigMap environment variables (populated via envFrom)
kubectl exec -it demo-configmap-secret-pod -- env | grep -E "SNOWFLAKE|S3"

# 3. Read mounted Secret files directly from /etc/secrets volume mount
kubectl exec -it demo-configmap-secret-pod -- cat /etc/secrets/SNOWFLAKE_USER
kubectl exec -it demo-configmap-secret-pod -- cat /etc/secrets/SNOWFLAKE_PASSWORD

Module 6: PySpark Reading Secrets from Volume Mount

Inspect PySpark code reading secrets directly from mounted files at `/etc/secrets/`.

Python — app/spark_s3_to_snowflake.py
import os
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, sum as _sum

def read_secret_file(secret_key):
    secret_path = f"/etc/secrets/{secret_key}"
    if os.path.exists(secret_path):
        with open(secret_path, "r") as f:
            return f.read().strip()
    return os.environ.get(secret_key, "")

# 1. Read ConfigMap variables (injected via envFrom)
s3_bucket = os.environ.get("S3_BUCKET", "my-data-lake-bucket")
sf_url = os.environ.get("SNOWFLAKE_URL")

# 2. Read Secret credentials directly from /etc/secrets Volume Mount
sf_user = read_secret_file("SNOWFLAKE_USER")
sf_password = read_secret_file("SNOWFLAKE_PASSWORD")

spark = SparkSession.builder.appName("EMR_EKS_S3_to_Snowflake").getOrCreate()

# Extract dataset from Amazon S3
df = spark.read.parquet(f"s3a://{s3_bucket}/data/input/sales_data.parquet")

# Write summary to Snowflake
df.write \
   .format("snowflake") \
   .option("sfURL", sf_url) \
   .option("sfUser", sf_user) \
   .option("sfPassword", sf_password) \
   .option("dbtable", "SALES_SUMMARY_MONTHLY") \
   .mode("overwrite") \
   .save()
  • Review PySpark Secret File Reader Understand how read_secret_file() opens /etc/secrets/SNOWFLAKE_PASSWORD to fetch credentials.

Module 7: Airflow EMR EKS Snowflake DAG Pipeline

Orchestrate the Spark job on EMR Virtual Cluster via Airflow `EmrContainerOperator`.

Python — dags/emr_eks_snowflake_dag.py
from airflow import DAG
from airflow.providers.amazon.aws.operators.emr import EmrContainerOperator

with DAG(
    dag_id="emr_eks_s3_to_snowflake_pipeline_dag",
    schedule_interval=None,
    catchup=False,
) as dag:

    submit_spark_snowflake_job = EmrContainerOperator(
        task_id="submit_spark_s3_to_snowflake_job",
        name="airflow-emr-eks-s3-snowflake-job",
        virtual_cluster_id="abc123def456ghi789",
        execution_role_arn="arn:aws:iam::123456789012:role/EMRJobExecutionRole",
        release_label="emr-6.10.0-latest",
        job_driver={
            "sparkSubmitJobDriver": {
                "entryPoint": "local:///opt/spark/work-dir/spark_s3_to_snowflake.py",
                "sparkSubmitParameters": (
                    "--conf spark.kubernetes.driver.podTemplateFile=s3://my-bucket/pod-templates/driver-pod-template.yaml "
                    "--conf spark.kubernetes.executor.podTemplateFile=s3://my-bucket/pod-templates/executor-pod-template.yaml "
                    "--packages net.snowflake:spark-snowflake_2.12:2.12.0-spark_3.3"
                ),
            }
        },
        aws_conn_id="aws_default",
        wait_for_completion=True,
    )
