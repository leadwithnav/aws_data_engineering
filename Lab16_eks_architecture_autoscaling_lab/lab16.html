Module 2: Control Plane & Shared Services Anatomy

Examine the AWS-managed control plane, cluster add-ons, and multi-tenant namespace boundaries.

Control Plane Responsibilities

AWS manages the EKS control plane across 3 Availability Zones (AZs) to guarantee high availability and fault tolerance:

  • Kube-API Server: Handles API calls, authenticates requests, and serves as the single source of interaction.
  • etcd: High-availability distributed key-value store holding the complete state of the cluster.
  • Kube-Scheduler: Assigns newly created pods to available nodes based on resource requests and nodeSelectors.
  • Controller Manager: Enforces cluster state loops (NodeController, ReplicaSetController, NamespaceController).

Shared Cluster Add-on Services

Service Object Name Function
CoreDNS coredns Internal cluster DNS resolution for Kubernetes services and pods.
VPC CNI Plugin aws-node Assigns native AWS VPC IP addresses directly to Kubernetes pods.
Metrics Server metrics-server Aggregates pod CPU/Memory metrics for HPA and Cluster Autoscaler.
Cluster Autoscaler cluster-autoscaler Dynamically adjusts EC2 Auto Scaling Group capacity based on pending pods.

Module 3: Worker Node Group Strategies

Compare Compute, Memory-Optimized, and Spot instance node group strategies.

💻 1. Compute Nodes On-Demand

General purpose compute workloads requiring balanced resources.

  • Instance Families: m6i, m7i, c6i, c7i
  • Ideal For: Microservices, REST APIs, Web Servers, CI/CD runners
  • Characteristics: Balanced CPU/RAM, predictable On-Demand pricing
🧠 2. Memory Nodes High RAM

Memory intensive workloads processing large datasets in-RAM.

  • Instance Families: r6i, r7i, x2idn, x2iedn
  • Ideal For: Redis, Memcached, Kafka, Spark, Flink, Elasticsearch
  • Characteristics: High RAM-to-vCPU ratio, fast memory throughput
⚡ 3. Spot Nodes 70-90% Savings

Cost-optimized interruptible capacity for resilient batch jobs.

  • Instance Families: Mixed EC2 Families (`m5`, `m6i`, `c5`, `r5`)
  • Ideal For: Spark workers, ETL jobs, ML training, Batch pipelines
  • Characteristics: Up to 90% discount, interruptible capacity
  • Compare Compute, Memory & Spot Node Strategies Analyze instance family selections, cost trade-offs, and workload placement criteria.

Module 5: EKS Auto Mode & Control Plane Tiers

Explore AWS EKS Auto Mode, Extended Version Support, and Control Plane Scaling Tiers.

ℹ️ AWS Managed Innovations
Amazon EKS provides options to automate routine node and cluster administration tasks:

1. EKS Auto Mode

EKS Auto Mode automates compute, storage, and networking tasks. AWS automatically provisions, patches, and scales compute infrastructure to meet application needs without requiring manual EC2 Auto Scaling Group setup.

2. Control Plane Scaling Tiers

  • Standard Tier: Control plane automatically scales dynamically with cluster growth.
  • Pre-Provisioned High-Performance Tiers: Pre-provisions control plane infrastructure with fixed high performance to eliminate scaling latency during massive traffic spikes.

3. Kubernetes Version Upgrade Policy

AWS provides Standard Support (14 months) and Extended Support (up to 26 months), automatically upgrading cluster minor versions when standard support ends to guarantee security compliance.

Module 6: AWS Console Node Group Management

Walk through managing EC2 Managed Node Groups and Fargate Profiles in the AWS Console.

Console Walkthrough: Adding a Node Group

  1. In the AWS Console, navigate to Amazon EKS -> Clusters and click your cluster.
  2. Select the Compute tab.
  3. Under Node groups, click Add node group.
  4. Specify Node group name (e.g. spark-node-group) and attach the Worker Node IAM Role.
  5. Select Capacity Type (On-Demand or Spot) and EC2 instance types (e.g. m6i.large).
  6. Set scaling boundaries: Minimum size (1), Desired size (2), and Maximum size (5).
  7. Click Create. AWS provisions the EC2 Auto Scaling Group and joins nodes to your EKS cluster.

Fargate Profiles (Serverless Pod Execution)

Fargate profiles allow running pods directly on AWS-managed microVMs without managing EC2 instances. Fargate automatically allocates exact CPU/Memory resources based on pod specs.
