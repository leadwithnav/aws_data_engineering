Module 1: Overview & Execution Concepts

Visualizing Jobs, Stages, Tasks, and Data Shuffles in Apache Spark.

💡 Learning Objective

Build a deep conceptual and visual understanding of how the Apache Spark Engine plans and executes data pipelines. Learn how user code translates into logical plans, DAG stages, tasks across worker nodes, and physical network shuffles.

Spark Execution Architecture Overview

Apache Spark uses a distributed runtime model to process large data volumes concurrently. Key execution components include:

  • Spark Driver: The master process managing the SparkSession, building the DAG of stages, and orchestrating worker tasks.
  • Spark Executors: Worker processes executing tasks on data partitions in memory or disk.
  • DAG (Directed Acyclic Graph): Spark's physical execution plan detailing how transformations stream into final actions.
  • Spark UI Dashboard: The live web portal (port 4040) used to inspect active jobs, stage DAGs, shuffle read/write bytes, and SQL plan trees.
  • Review Execution Architecture Understand the role of Driver, Executor nodes, DAG DAGs, and Spark UI metrics.

Module 2: Driver, Executors & Execution Hierarchy

Mapping code actions to Jobs, Stages, Tasks, and Data Partitions.

Spark Architectural Roles

  • Spark Driver (Master): Hosts the main program entry point (SparkSession). Analyzes code, constructs logical & physical plans, schedules tasks, and collects results.
  • Spark Executors (Workers): Isolated processes running on cluster nodes. They execute assigned tasks, perform compute operations on data partitions, and write output.

Execution Abstraction Hierarchy

Abstraction Level Description Trigger / Scope
Job Highest unit of execution. Created whenever a Spark Action is called (e.g. .write.save(), .count()). Triggered by Action
Stage A set of parallel tasks executing identical compute logic without network data movement. Bounded by Shuffles
Task The smallest unit of work. Executed by 1 CPU core on 1 partition. 1 Task per Partition
Partition A physical split of a large dataset processed in memory by worker nodes. Data Chunk

Module 3: Narrow vs. Wide Transformations

Understanding data dependencies and shuffle boundary generation.

⚠️ The Performance Impact of Shuffles

Wide transformations require shuffling data across worker nodes over the network. Network I/O and disk serialization during shuffles are the primary bottleneck in big data pipelines.

1. Narrow Transformations (No Shuffle)

Operations where each input partition contributes to exactly one output partition. Data remains inside the memory of the executing worker node without network transfers.

PySpark Code
# Narrow operations: Pipelined within a single Stage
filtered_df = df.filter(df["Amount"] > 100.0) \
                .select("OrderID", "CustomerID", "Amount")

2. Wide Transformations (Triggers Network Shuffle)

Operations where input partitions contribute to multiple output partitions. Spark must redistribute records across cluster nodes based on key hashes, splitting the job into distinct Stages.

PySpark Code
# Wide operation: Triggers a Shuffle Exchange boundary and starts Stage 1
grouped_df = df.groupBy("Category").sum("Amount")
  • Identify Transformation Dependencies Distinguish narrow operations (filter, select) from wide operations (groupBy, join).

Module 5: Notebook Execution & UI Exploration

Executing notebook cells and inspecting physical DAG plans in the Spark UI.

Key Experiments & Spark UI Observations

1. Schema Inference & Job Creation

Observe how data loading behaves based on schema settings:

  • inferSchema=false: Creates 1 Job to read file header lines.
  • inferSchema=true: Creates 2 Jobs (Job 1 scans sample rows to infer column datatypes; Job 2 loads the dataset).

2. Actions vs. Transformations

Transformations are lazy and create no jobs. Calling an Action triggers actual execution:

PySpark Code
# Trigger write action without displaying console truncation
final_report.write.mode("overwrite").format("noop").save()

3. Spark UI Tabs to Inspect

  • Jobs Tab: Lists completed & active jobs, job duration, and total completed stages.
  • Stages Tab: Displays stage DAG visualizations, task completion progress, and Shuffle Read / Shuffle Write payload metrics.
  • SQL / DataFrame Tab: Visualizes physical query execution plan nodes (FileScan, HashAggregate, Exchange).
  • Complete Notebook Experiments Execute all cells in `spark_execution_fundamentals.ipynb` and analyze the DAGs in Spark UI.
