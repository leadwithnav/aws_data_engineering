Module 2: Provision EKS Cluster & Managed Node Group

Deploying Amazon EKS with auto-scaling m5.xlarge managed nodes and OIDC enabled.

1. EKS Cluster Definition Manifest (`eks_cluster.yaml`)

Save the following YAML configuration file as eks_cluster.yaml on your administrative machine:

YAML Manifest (eks_cluster.yaml)
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: spark-eks-cluster
  region: us-west-2
  version: "1.28"

iam:
  withOIDC: true  # REQUIRED for IRSA and EMR on EKS Virtual Cluster bindings

managedNodeGroups:
  - name: m5-xlarge-workers
    instanceType: m5.xlarge  # 4 vCPUs, 16 GB RAM per node (or m6i.xlarge)
    minSize: 3              # Minimum node capacity
    desiredCapacity: 4      # Initial training capacity
    maxSize: 8              # Auto-scale up to 8 nodes during peak loads
    volumeSize: 100          # 100 GB root EBS volume
    volumeType: gp3
    privateNetworking: true
    labels:
      role: spark-worker
    tags:
      Environment: Training
      Project: AWS-Data-Engineering-Lab

2. Deploy EKS Cluster via `eksctl`

⚠️ Deployment Duration Note

EKS cluster provisioning via eksctl takes approximately 15 to 20 minutes. Ensure your administrative AWS CLI session remains active.

CLI Terminal
# 1. Provision cluster
eksctl create cluster -f eks_cluster.yaml

# 2. Verify worker nodes online & status ACTIVE
aws eks describe-cluster --name spark-eks-cluster --region us-west-2 --query "cluster.status" --output text
kubectl get nodes -o wide
  • Provision EKS Cluster & Verify Node Group Deploy EKS cluster with m5.xlarge managed nodes (3-8 auto-scaling) and OIDC provider enabled.

Module 3: Create 25 Student Namespaces & RBAC

Automated provisioning of 25 isolated Kubernetes namespaces (student-01 to student-25).

Automated Script: Provision 25 Namespaces & ServiceAccounts

PowerShell Script
# Create 25 Kubernetes student namespaces and apply Spark ServiceAccounts
1..25 | ForEach-Object {
    $i = "{0:D2}" -f $_
    $ns = "student-$i"
    Write-Host "Creating Namespace and RBAC for $ns..." -ForegroundColor Green
    
    kubectl create namespace $ns --dry-run=client -o yaml | kubectl apply -f -
    
    # Apply ServiceAccount and RBAC RoleBinding inside namespace
    $rbacYaml = @"
apiVersion: v1
kind: ServiceAccount
metadata:
  name: spark
  namespace: $ns
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: spark-role
  namespace: $ns
rules:
  - apiGroups: [""]
    resources: ["pods", "services", "configmaps", "persistentvolumeclaims"]
    verbs: ["create", "get", "list", "watch", "delete", "deletecollection", "patch"]
  - apiGroups: [""]
    resources: ["pods/log"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: spark-role-binding
  namespace: $ns
subjects:
  - kind: ServiceAccount
    name: spark
    namespace: $ns
roleRef:
  kind: Role
  name: spark-role
  apiGroup: rbac.authorization.k8s.io
"@
    $rbacYaml | kubectl apply -f -
}

Module 4: IAM Execution Roles & S3 Storage

Creating EMR Containers Job Execution Role and S3 Training Data Storage.

1. Create S3 Bucket for Training Materials & Job Outputs

AWS CLI
# Create unique S3 bucket for training materials
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
BUCKET_NAME="aws-spark-training-data-${AWS_ACCOUNT_ID}"

aws s3api create-bucket --bucket $BUCKET_NAME --region us-west-2 --create-bucket-configuration LocationConstraint=us-west-2
echo "Created Training S3 Bucket: s3://$BUCKET_NAME"

2. Create EMR on EKS Job Execution IAM Role

AWS CLI
# 1. Generate trust policy for EMR on EKS containers service
cat <<EOF > trust-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "emr-containers.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
EOF

# 2. Create IAM Role
aws iam create-role --role-name EMRContainersJobExecutionRole --assume-role-policy-document file://trust-policy.json

# 3. Attach S3 access and CloudWatch logs policies
aws iam attach-role-policy --role-name EMRContainersJobExecutionRole --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
aws iam attach-role-policy --role-name EMRContainersJobExecutionRole --policy-arn arn:aws:iam::aws:policy/CloudWatchLogsFullAccess
  • Provision S3 Storage & IAM Execution Role Create S3 training bucket and `EMRContainersJobExecutionRole` with emr-containers.amazonaws.com trust policy.

Module 5: Create 25 EMR Virtual Clusters

Mapping one EMR on EKS Virtual Cluster to each student namespace (25 total VCs).

Automated Script: Create 25 Virtual Clusters

PowerShell Script
# Create 25 EMR on EKS Virtual Clusters mapped to student-01..25 namespaces
1..25 | ForEach-Object {
    $i = "{0:D2}" -f $_
    $ns = "student-$i"
    $vcName = "emr-vc-$ns"
    Write-Host "Creating EMR Virtual Cluster $vcName for namespace $ns..." -ForegroundColor Cyan
    
    $containerProvider = "{`"id`": `"spark-eks-cluster`", `"type`": `"EKS`", `"info`": {`"eksInfo`": {`"namespace`": `"$ns`"}}}"
    
    aws emr-containers create-virtual-cluster `
      --name $vcName `
      --container-provider $containerProvider `
      --region us-west-2
}
Bash Script
#!/bin/bash
# Create 25 EMR on EKS Virtual Clusters mapped to student-01..25 namespaces
for i in $(seq -w 1 25 2>/dev/null || printf "%02d\n" {1..25}); do
  ns="student-${i}"
  vcName="emr-vc-${ns}"
  echo "Creating EMR Virtual Cluster ${vcName} for namespace ${ns}..."
  
  providerJson=$(printf '{"id": "spark-eks-cluster", "type": "EKS", "info": {"eksInfo": {"namespace": "%s"}}}' "${ns}")
  
  aws emr-containers create-virtual-cluster \
    --name "${vcName}" \
    --container-provider "${providerJson}" \
    --region us-west-2
done

Verify Active EMR Virtual Clusters

AWS CLI
# List all virtual clusters and confirm RUNNING status

Module 6: Student Access & Credential Provisioning

Distributing AWS CLI access (Standard IAM Access Keys vs AWS SSO) and EKS kubeconfig.

Option A: Standard IAM User Credentials

If providing IAM Users to students, assign policies AmazonEKSClusterPolicy, AmazonEC2ContainerRegistryPowerUser, and AmazonS3FullAccess. Students will run:

Student CLI Command
aws configure
# Prompts for student Access Key ID and Secret Access Key

aws eks update-kubeconfig --name spark-eks-cluster --region us-west-2

Option B: AWS SSO / IAM Identity Center (Profile: `student`)

If using AWS SSO / Identity Center, configure student SSO start URL and role name:

Student CLI Command
# Student configures SSO session
aws configure sso --profile student

# Authenticate & export profile
aws sso login --profile student
export AWS_PROFILE=student  # (or $env:AWS_PROFILE="student" in PowerShell)

aws eks update-kubeconfig --name spark-eks-cluster --region us-west-2
