Module 1: Overview & Architecture

Serverless Apache Spark Workload Orchestration via Amazon EMR on EKS.

⚠️ Important: Platform Team Provisioning vs. Data Engineer Role

In enterprise production environments, the EMR Virtual Cluster and IAM Execution Role are created and managed by the Platform / Cloud Infrastructure Team.

As a Data Engineer, you will receive these pre-created details (Cluster ID, Execution Role ARN, and ECR Repository URL) to submit your Spark applications to EKS via EMR on EKS!

☁️ AWS CloudShell Support

You can run docker build and docker push on your local workstation (or CloudShell with ECR push). Once the image is pushed to ECR, you can run 100% of job submission and pod monitoring commands directly in AWS CloudShell without needing local tools!

Module 2: Platform Provisioning (Reference)

Understanding how the Platform Team creates EMR Virtual Clusters and IAM Execution Roles.

⚠️ Platform Team Warning Callout

Note for Data Engineers: The commands below are performed by your Platform / DevOps Team during initial infrastructure setup. In this lab, these resources are pre-provisioned for you. Review this step to understand how your Virtual Cluster and IAM Role are configured under the hood!

1. Create Kubernetes Namespace `spark-emr` (Platform Task)

Before linking EMR to EKS, the Platform Team creates a designated Kubernetes namespace for Spark workloads.

Kubectl CLI
kubectl create namespace spark-emr

2. Create IAM Job Execution Role (Platform Task)

The Platform Team creates an IAM Role for EMR with trust policies allowing emr-containers.amazonaws.com to assume the role and access S3 data.

PowerShell
# Define IAM Trust Policy JSON
$TrustPolicy = '{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "emr-containers.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }
  ]
}'

# Create IAM Execution Role
aws iam create-role --role-name EMRJobExecutionRole --assume-role-policy-document $TrustPolicy

# Attach S3 Access Policy
aws iam attach-role-policy --role-name EMRJobExecutionRole --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
Terminal

aws iam create-role --role-name EMRJobExecutionRole --assume-role-policy-document '{

  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Service": "emr-containers.amazonaws.com" },
    "Action": "sts:AssumeRole"
  }]
}'

# Attach S3 Access Policy
aws iam attach-role-policy --role-name EMRJobExecutionRole --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess

3. Create EMR Virtual Cluster on EKS (Platform Task)

The Platform Team links an EKS namespace to Amazon EMR by creating an EMR Virtual Cluster mapping.

PowerShell
aws emr-containers create-virtual-cluster `
  --name "spark-emr-vc" `
  --container-provider "{
    `"id`": `"spark-eks-cluster`",
    `"type`": `"EKS`",
    `"info`": {
      `"eksInfo`": { `"namespace`": `"spark-emr`" }
    }
  }"
Terminal
aws emr-containers create-virtual-cluster \
  --name "spark-emr-vc" \
  --container-provider '{
    "id": "spark-eks-cluster",
    "type": "EKS",
    "info": {
      "eksInfo": { "namespace": "spark-emr" }
    }
  }'

4. Check Execution Role & Retrieve ARN

Verify that the IAM Execution Role exists and fetch its exact Amazon Resource Name (ARN):

PowerShell
# Query IAM Role and fetch ARN
$EXECUTION_ROLE_ARN = (aws iam get-role --role-name EMRJobExecutionRole --query "Role.Arn" --output text)
Write-Host "Execution Role ARN: $EXECUTION_ROLE_ARN"
Terminal
# Query IAM Role and fetch ARN
EXECUTION_ROLE_ARN=$(aws iam get-role --role-name EMRJobExecutionRole --query "Role.Arn" --output text)
echo "Execution Role ARN: $EXECUTION_ROLE_ARN"

Module 4: Build & Push Custom EMR Image

Building Spark container image on official EMR base runtime and pushing to your ECR repo.

1. Explore Dockerfile (`app/Dockerfile`)

Dockerfile
# Official Amazon EMR on EKS base runtime image (version 6.10.0)
FROM public.ecr.aws/emr-on-eks/spark/emr-6.10.0:latest

# Switch to root for administration
USER root
RUN mkdir -p /opt/spark/work-dir

COPY spark_app.py /opt/spark/work-dir/spark_app.py
COPY sample_data.csv /opt/spark/work-dir/sample_data.csv

# Assign permissions to default EMR user (hadoop: UID 1000)
RUN chown -R hadoop:hadoop /opt/spark/work-dir

# Switch to non-root execution user
USER hadoop
WORKDIR /opt/spark/work-dir

2. Build x86_64 Image

PowerShell
cd d:\trainings\aws_data_engineering\Lab9_spark_on_emr_eks\app
docker build --platform linux/amd64 -t spark-emr-eks:latest .
Terminal
cd ~/trainings/aws_data_engineering/Lab9_spark_on_emr_eks/app
docker build --platform linux/amd64 -t spark-emr-eks:latest .

3. Authenticate Docker CLI & Push to ECR Repo

PowerShell
# Extract base registry domain from ECR_REPO_URL
$RegistryUrl = $env:ECR_REPO_URL.Split("/")[0]

# Authenticate Docker CLI
aws ecr get-login-password --region $env:AWS_REGION | docker login --username AWS --password-stdin $RegistryUrl

# Tag and Push image
docker tag spark-emr-eks:latest "$env:ECR_REPO_URL:latest"
docker push "$env:ECR_REPO_URL:latest"
Terminal
# Extract base registry domain from ECR_REPO_URL
RegistryUrl=$(echo $ECR_REPO_URL | cut -d'/' -f1)

# Authenticate Docker CLI
aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $RegistryUrl

# Tag and Push image
docker tag spark-emr-eks:latest "$ECR_REPO_URL:latest"
docker push "$ECR_REPO_URL:latest"
  • Build & Push EMR Container Image Build image using `public.ecr.aws/emr-on-eks/spark/emr-6.10.0:latest` base and push `$ECR_REPO_URL:latest` to ECR.

Module 5: Submit & Monitor EMR Job

Submitting containerized PySpark jobs to Amazon EMR Virtual Cluster via CLI.

1. Submit Job Run (`aws emr-containers start-job-run`)

PowerShell
aws emr-containers start-job-run `
  --virtual-cluster-id $env:VIRTUAL_CLUSTER_ID `
  --name "spark-emr-eks-job" `
  --execution-role-arn $env:EXECUTION_ROLE_ARN `
  --release-label "emr-6.10.0-latest" `
  --job-driver "{
    `"sparkSubmitJobDriver`": {
      `"entryPoint`": `"local:///opt/spark/work-dir/spark_app.py`",
      `"sparkSubmitParameters`": `"--conf spark.kubernetes.container.image=$env:ECR_REPO_URL:latest --conf spark.executor.instances=1 --conf spark.driver.memory=512m --conf spark.executor.memory=512m`"
    }
  }"
Terminal
aws emr-containers start-job-run \
  --virtual-cluster-id $VIRTUAL_CLUSTER_ID \
  --name "spark-emr-eks-job" \
  --execution-role-arn $EXECUTION_ROLE_ARN \
  --release-label "emr-6.10.0-latest" \
  --job-driver '{
    "sparkSubmitJobDriver": {
      "entryPoint": "local:///opt/spark/work-dir/spark_app.py",
      "sparkSubmitParameters": "--conf spark.kubernetes.container.image='"$ECR_REPO_URL"':latest --conf spark.executor.instances=1 --conf spark.driver.memory=512m --conf spark.executor.memory=512m"
    }
  }'
AWS CloudShell

  --virtual-cluster-id $VIRTUAL_CLUSTER_ID \
  --name "spark-emr-eks-job" \
  --execution-role-arn $EXECUTION_ROLE_ARN \
  --release-label "emr-6.10.0-latest" \

2. Track Job Execution Status

PowerShell
