Module 1: Observability Architecture & Overview

End-to-End Metrics Scraping & Visualization Pipeline using Helm, Prometheus, and Grafana on Minikube.

💡 Learning Objective

Deploy the industry-standard kube-prometheus-stack via Helm. Instrument both a Python Flask microservice (using prometheus-flask-exporter) and an Apache Spark cluster (via Prometheus JMX metrics sink), scrape their metrics, and visualize active performance on custom Grafana Dashboards.

Monitoring Stack Component Responsibilities

Component Deployment Method Primary Function
Helm CLI Tool Kubernetes Package Manager automating chart installation and configuration.
Prometheus Server Helm Chart (kube-prometheus-stack) Time-series database that pulls (scrapes) metrics from target HTTP endpoints.
Grafana Helm Chart (bundled or standalone) Visualization UI platform providing real-time interactive monitoring dashboards.
Flask Microservice Python App with prometheus-flask-exporter Exposes HTTP metrics on /metrics (request rates, latency, status codes).
Apache Spark Spark Metrics Sink (Prometheus/JMX) Exposes JVM memory, active executors, task execution time, and GC pause metrics.

Module 4: 3. Instrument Flask App & Configure Scraping

Adding Prometheus metric exporters to Python Flask and deploying a ServiceMonitor.

1. Python Flask Application (`app.py`) & Dockerfile

Instrumentation using prometheus_flask_exporter exposes automatic HTTP metrics on /metrics:

Python (app.py)
from flask import Flask
from prometheus_flask_exporter import PrometheusMetrics

app = Flask(__name__)
metrics = PrometheusMetrics(app)

@app.route('/')
def home():
    return "Flask Microservice Active!"

@app.route('/api/data')
def get_data():
    return {"status": "success", "records": 100}

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
Dockerfile
FROM python:3.11-slim
WORKDIR /app
RUN pip install flask prometheus-flask-exporter
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]

2. Build Image on Minikube & Deploy to `apps` Namespace

Build the container image directly into Minikube's Docker daemon so no external registry push is required:

Minikube & Kubectl CLI
# Step A: Point local Docker CLI to Minikube's internal Docker daemon
minikube image build -t flask-prometheus-app:v1 .

# Step B: Create separate application namespace
kubectl create namespace apps

# Step C: Deploy Flask Application & Service in 'apps' namespace
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: flask-app
  namespace: apps
  labels:
    app: flask-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: flask-app
  template:
    metadata:
      labels:
        app: flask-app
    spec:
      containers:
      - name: flask-container
        image: flask-prometheus-app:v1
        imagePullPolicy: Never
        ports:
        - containerPort: 5000
          name: http
---
apiVersion: v1
kind: Service
metadata:
  name: flask-service
  namespace: apps
  labels:
    app: flask-app
spec:
  ports:
  - port: 5000
    targetPort: 5000
    name: http
  selector:
    app: flask-app
EOF

3. Cross-Namespace Scraping via ServiceMonitor

Deploy the ServiceMonitor in the apps namespace. Enable cross-namespace scraping in Prometheus (in monitoring namespace):

YAML Manifest & Helm Upgrade
# Step A: Apply ServiceMonitor in 'apps' namespace targeting flask-service
cat <<EOF | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: flask-app-monitor
  namespace: apps
  labels:
    release: prometheus-stack
spec:
  selector:
    matchLabels:
      app: flask-app
  endpoints:
  - port: http
    path: /metrics
    interval: 15s
EOF

# Step B: Upgrade Prometheus Helm release to enable cross-namespace ServiceMonitor discovery
helm upgrade prometheus-stack prometheus-community/kube-prometheus-stack `
  --namespace monitoring `
  --set prometheus.prometheusSpec.serviceMonitorNamespaceSelector={} `
  --set prometheus.prometheusSpec.serviceMonitorSelectorNilUsesHelmValues=false
app: flask-app endpoints: - port: http path: /metrics interval: 15s
  • Instrument Flask App & Deploy ServiceMonitor Expose /metrics endpoint using prometheus_flask_exporter and apply ServiceMonitor CRD.

Module 4: 4. Instrument Apache Spark Metrics

Enabling Spark Prometheus metrics sink for Driver and Executor JVM tracking.

1. Spark Metrics Configuration (`metrics.properties`)

Spark Config File
# Enable Prometheus Servlet Metrics Sink for Spark Driver & Executor
*.sink.prometheusServlet.class=org.apache.spark.metrics.sink.PrometheusServlet
*.sink.prometheusServlet.path=/metrics/prometheus
driver.sink.prometheusServlet.class=org.apache.spark.metrics.sink.PrometheusServlet
executor.sink.prometheusServlet.class=org.apache.spark.metrics.sink.PrometheusServlet

2. Spark Submit Pod Annotations for Prometheus Scraping

Spark Submit Configs
--conf spark.ui.prometheus.enabled=true \
--conf spark.kubernetes.driver.annotation.prometheus.io/scrape=true \
--conf spark.kubernetes.driver.annotation.prometheus.io/port=4040 \
--conf spark.kubernetes.driver.annotation.prometheus.io/path=/metrics/executors/prometheus \
--conf spark.kubernetes.executor.annotation.prometheus.io/scrape=true \
--conf spark.kubernetes.executor.annotation.prometheus.io/port=4040
  • Enable Spark Prometheus Metrics Sink Configure PrometheusServlet sink and add Pod annotations for Driver and Executor scraping.

Module 6: 5. Build Custom Grafana Dashboards

Creating interactive visualization panels for Flask HTTP throughput and Spark JVM execution.

1. Key PromQL Queries for Flask & Spark

Dashboard Target Metric / Panel Name PromQL Query Expression
Flask App HTTP Request Throughput (req/sec) rate(flask_http_request_total[5m])
Flask App 95th Percentile Latency (seconds) histogram_quantile(0.95, rate(flask_http_request_duration_seconds_bucket[5m]))
Spark Cluster Active Executor Count metrics_spark_executor_count
Spark Cluster JVM Heap Memory Used (Bytes) metrics_spark_jvm_heap_used_bytes
Spark Cluster JVM GC Pause Time (ms) rate(metrics_spark_jvm_GC_time_total[5m])
