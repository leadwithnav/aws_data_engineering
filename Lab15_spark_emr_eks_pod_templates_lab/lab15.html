Module 1: Overview & Architecture

Orchestrate production Spark workloads on Amazon EMR on EKS using Apache Airflow & Pod Templates.

💡 Production Orchestration Pattern
In modern data engineering architectures, Spark applications on EMR on EKS are submitted programmatically by Apache Airflow using the EmrContainerOperator. Airflow handles DAG scheduling, SLA tracking, retries, parameter passing, and pod template configuration.

Architectural Workflow

Architecture Flow 
[ Local Docker Compose (Airflow) ] ──> [ EmrContainerOperator ] ──> [ AWS EMR Containers API ]
                                                                               │
[ Pod Templates in S3 / Image ] ───────────────────────────────────────────────┼──> [ EKS Cluster ]
                                                                               │      ├── Spark Driver Pod
[ Custom PySpark Image in ECR ] ───────────────────────────────────────────────┘      └── Spark Executor Pods

Module Objectives

  • Spin up a local multi-container Apache Airflow stack using docker-compose.yaml.
  • Configure AWS credentials and aws_default connection inside Airflow.
  • Author an Airflow DAG using EmrContainerOperator to trigger EMR on EKS job runs.
  • Pass Spark Configuration Parameters and Driver/Executor Pod Templates dynamically.
  • Trigger the DAG and inspect running Driver and Executor pods in Amazon EKS.
  • Review Airflow + EMR on EKS Architecture Understand how Apache Airflow orchestrates EMR Virtual Cluster job runs on Kubernetes.

Module 2: Local Airflow & CLI Credentials Setup

Launch a local Apache Airflow stack using Docker Compose and supply AWS credentials via CLI without storing secrets in .env.

🔐 Security Best Practice
AWS Access Key ID and Secret Access Key should NEVER be hardcoded or saved inside .env files. Choose one of the secure CLI methods below to supply credentials dynamically.

2.1 Supply AWS Credentials via CLI (3 Options)

Option A: Mount Host AWS CLI Credentials (~/.aws)

If you have already run aws configure on your machine, Airflow automatically reads your host AWS credentials via Docker volume mount (~/.aws:/home/airflow/.aws:ro).

Host CLI 
# Verify host credentials & launch Airflow
aws sts get-caller-identity
docker compose up -d --build

Option B: Pass Environment Variables on Terminal CLI

Bash / Zsh 
export AWS_ACCESS_KEY_ID="YOUR_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="YOUR_SECRET_ACCESS_KEY"
export AWS_DEFAULT_REGION="us-west-2"

docker compose up -d --build
PowerShell 
$env:AWS_ACCESS_KEY_ID = "YOUR_ACCESS_KEY_ID"
$env:AWS_SECRET_ACCESS_KEY = "YOUR_SECRET_ACCESS_KEY"
$env:AWS_DEFAULT_REGION = "us-west-2"

docker compose up -d --build

Option C: Configure Airflow Connection via Airflow CLI

Airflow Container CLI 
docker compose exec airflow-webserver airflow connections add 'aws_default' \
  --conn-type 'aws' \
  --conn-login 'YOUR_ACCESS_KEY_ID' \
  --conn-password 'YOUR_SECRET_ACCESS_KEY' \
  --conn-extra '{"region_name": "us-west-2"}'
  • Pass AWS Credentials via CLI & Start Airflow Supply AWS credentials via host ~/.aws mount or CLI environment variables, then run docker compose up -d.
  • Access Airflow Web UI & Verify Connection Navigate to http://localhost:8080 (admin / admin) and confirm active AWS connection.

Module 3: Driver & Executor Pod Templates

Author Kubernetes Pod Template YAML files for driver and executor pod customizations.

3.1 Driver Pod Template (pod-templates/driver-pod-template.yaml)

YAML — driver-pod-template.yaml 
apiVersion: v1
kind: Pod
metadata:
  name: spark-driver-template
  labels:
    app.kubernetes.io/component: driver
    tier: analytics-driver
  annotations:
    prometheus.io/scrape: "true"
    prometheus.io/port: "4040"
spec:
  containers:
    - name: spark-kubernetes-driver
      env:
        - name: ENVIRONMENT
          value: "production"
      volumeMounts:
        - name: driver-spark-local-dir
          mountPath: /data/spark-scratch
  volumes:
    - name: driver-spark-local-dir
      emptyDir:
        medium: Memory
        sizeLimit: 1Gi

3.2 Executor Pod Template (pod-templates/executor-pod-template.yaml)

YAML — executor-pod-template.yaml 
apiVersion: v1
kind: Pod
metadata:
  name: spark-executor-template
  labels:
    app.kubernetes.io/component: executor
    tier: analytics-executor
spec:
  containers:
    - name: spark-kubernetes-executor
      env:
        - name: SPARK_JAVA_OPT_G1GC
          value: "-XX:+UseG1GC -XX:InitiatingHeapOccupancyPercent=35"
      volumeMounts:
        - name: executor-spark-local-dir
          mountPath: /data/spark-scratch
  volumes:
    - name: executor-spark-local-dir
      emptyDir: {}
  • Create Pod Template YAML Manifests Verify driver-pod-template.yaml and executor-pod-template.yaml in pod-templates/ folder.

Module 4: Packaging & Image Build

Upload pod templates to S3 and push your custom PySpark image to Amazon ECR.

Bash / Zsh 
# 1. Upload Pod Templates to S3
aws s3 cp pod-templates/driver-pod-template.yaml s3://${S3_BUCKET}/pod-templates/driver-pod-template.yaml
aws s3 cp pod-templates/executor-pod-template.yaml s3://${S3_BUCKET}/pod-templates/executor-pod-template.yaml

# 2. Build & Push Custom EMR Docker Image
cd app
docker build --platform linux/amd64 -t spark-emr-pod-templates:latest .

RegistryUrl=$(echo $ECR_REPO_URL | cut -d'/' -f1)
aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $RegistryUrl
docker tag spark-emr-pod-templates:latest "$ECR_REPO_URL:v1"
docker push "$ECR_REPO_URL:v1"
PowerShell 
# 1. Upload Pod Templates to S3
aws s3 cp pod-templates/driver-pod-template.yaml "s3://$env:S3_BUCKET/pod-templates/driver-pod-template.yaml"
aws s3 cp pod-templates/executor-pod-template.yaml "s3://$env:S3_BUCKET/pod-templates/executor-pod-template.yaml"

# 2. Build & Push Custom EMR Docker Image
cd app
docker build --platform linux/amd64 -t spark-emr-pod-templates:latest .

$RegistryUrl = $env:ECR_REPO_URL.Split("/")[0]
aws ecr get-login-password --region $env:AWS_REGION | docker login --username AWS --password-stdin $RegistryUrl
docker tag spark-emr-pod-templates:latest "$env:ECR_REPO_URL:v1"
docker push "$env:ECR_REPO_URL:v1"
  • Upload Templates to S3 & Push Container to ECR Upload YAML files to S3 bucket and push tagged v1 container image to Amazon ECR.

Module 5: Airflow EmrContainerOperator DAG

Inspect and author the Python DAG orchestrating EMR on EKS job submission.

Python — dags/emr_eks_spark_dag.py 
import os
from datetime import datetime, timedelta
from airflow import DAG
from airflow.providers.amazon.aws.operators.emr import EmrContainerOperator

default_args = {
    "owner": "data_engineering_team",
    "start_date": datetime(2026, 7, 28),
    "retries": 1,
}

with DAG(
    dag_id="emr_eks_spark_pod_templates_dag",
    default_args=default_args,
    schedule_interval=None,
    catchup=False,
) as dag:

    submit_emr_eks_spark_job = EmrContainerOperator(
        task_id="submit_spark_job_to_emr_eks",
        name="airflow-emr-eks-spark-pod-templates-job",
        virtual_cluster_id=os.environ.get("VIRTUAL_CLUSTER_ID", "abc123def456ghi789"),
        execution_role_arn=os.environ.get("EXECUTION_ROLE_ARN", "arn:aws:iam::123456789012:role/EMRJobExecutionRole"),
        release_label="emr-6.10.0-latest",
        job_driver={
            "sparkSubmitJobDriver": {
                "entryPoint": "local:///opt/spark/work-dir/spark_app.py",
                "sparkSubmitParameters": (
                    "--conf spark.kubernetes.container.image=" + os.environ.get("ECR_REPO_URL") + ":v1 "
                    "--conf spark.kubernetes.driver.podTemplateFile=s3://" + os.environ.get("S3_BUCKET") + "/pod-templates/driver-pod-template.yaml "
                    "--conf spark.kubernetes.executor.podTemplateFile=s3://" + os.environ.get("S3_BUCKET") + "/pod-templates/executor-pod-template.yaml "
                    "--conf spark.driver.memory=1024m "
                    "--conf spark.executor.memory=1024m "
                    "--conf spark.executor.instances=2 "
                    "--conf spark.sql.adaptive.enabled=true"
                ),
            }
        },
        aws_conn_id="aws_default",
        wait_for_completion=True,
    )
  • Deploy Airflow DAG File Verify emr_eks_spark_dag.py is present in the dags/ directory and loaded by Airflow scheduler.

Module 6: Triggering DAG & Pod Inspection

Trigger the DAG from Airflow Web UI and inspect running Driver and Executor pods in EKS.

Bash / Zsh 
# Option A: Trigger DAG via Airflow CLI inside docker
docker compose exec airflow-scheduler airflow dags trigger emr_eks_spark_pod_templates_dag

# Option B: Connect kubectl to EKS and inspect pods
aws eks update-kubeconfig --name spark-eks-cluster --region us-west-2

# List running Spark pods
kubectl get pods -n spark-emr -l app.kubernetes.io/name=spark-job

# Inspect merged driver pod specification
kubectl get pod -n spark-emr -l app.kubernetes.io/component=driver -o yaml

# Stream logs from driver pod
kubectl logs -n spark-emr -l app.kubernetes.io/component=driver -f
