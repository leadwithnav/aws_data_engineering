Module 1: Overview & Architecture

Packaging Apache Spark & PySpark applications into isolated Docker containers.

💡 Learning Objective

Containerization wraps software, libraries, configurations, and datasets in an isolated filesystem image that runs uniformly across machines. Learn how to package PySpark scripts and data files into official Apache Spark base images, manage unprivileged runtime user permissions (user 185), and execute local Spark aggregations inside containers.

Module 2: Explore App & Dataset

Inspecting PySpark job code and input transaction CSV files.

1. PySpark Application (`app/spark_app.py`)

Inspect the PySpark execution script that loads CSV data, prints schemas, and performs Category revenue aggregations:

Python Code (spark_app.py)
import sys
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, sum as _sum, count, round as _round

def main():
    # Initialize SparkSession for local container execution
    spark = SparkSession.builder \
        .appName("SparkContainerizationDemo") \
        .getOrCreate()
    
    # Suppress verbose log warnings
    spark.sparkContext.setLogLevel("ERROR")
    
    print("=" * 50)
    print("Starting Spark Application inside Container...")
    print("=" * 50)
    
    data_path = "/opt/spark/work-dir/sample_data.csv"
    print(f"Reading transaction data from {data_path}...")
    
    # Read CSV with schema inference
    df = spark.read.csv(data_path, header=True, inferSchema=True)
    
    print("\nInput Schema details:")
    df.printSchema()
    
    print("\nFirst 5 transactions:")
    df.show(5)
    
    print("\nAggregating sales revenue by category...")
    agg_df = df.groupBy("Category").agg(
        count("OrderID").alias("TotalOrders"),
        _round(_sum("Amount"), 2).alias("TotalRevenue")
    ).orderBy(col("TotalRevenue").desc())
    
    print("\nAggregation Summary Results:")
    agg_df.show()
    
    spark.stop()
    print("Spark Session stopped successfully.")

if __name__ == "__main__":
    main()

Module 3: Dockerfile & Permissions

Configuring base image, working directory, and unprivileged user 185 ownership.

Production Dockerfile (`app/Dockerfile`)

Dockerfile
# Official Apache Spark base image
FROM apache/spark:3.5.1

# Switch to root temporarily to copy files into system paths
USER root

# Set working directory inside Spark home
WORKDIR /opt/spark/work-dir

# Copy PySpark application script and dataset
COPY spark_app.py /opt/spark/work-dir/
COPY sample_data.csv /opt/spark/work-dir/

# Change ownership of work-dir to default Spark unprivileged user 185
RUN chown -R 185:185 /opt/spark/work-dir

# Switch back to unprivileged user 185 for secure container execution
USER 185

Spark Dockerfile Directive Breakdown

Directive Technical Function
FROM apache/spark:3.5.1 Base image pre-configured with Java 17, PySpark 3.5.1, Hadoop binaries, and Spark CLIs.
USER root Elevates privileges during build phase to copy files and modify system folder ownership.
chown -R 185:185 Assigns directory permission to user ID 185, preventing permission denied errors when Spark writes temporary shuffle data.
USER 185 Switches back to standard Spark unprivileged user for runtime container security.
  • Configure Dockerfile & Permissions Set `apache/spark:3.5.1` base image, copy workspace assets, and configure user 185 ownership.

Module 4: Manual Build & Run

Building the custom Spark image tag and triggering spark-submit inside the container.

1. Build Image (`docker build`)

PowerShell
cd d:\trainings\aws_data_engineering\Lab4_spark_containerization\app
docker build -t spark-containerization:latest .
Terminal
cd ~/trainings/aws_data_engineering/Lab4_spark_containerization/app
docker build -t spark-containerization:latest .

2. Run Container with `spark-submit`

PowerShell
docker run --rm -it spark-containerization:latest /opt/spark/bin/spark-submit /opt/spark/work-dir/spark_app.py
Terminal
docker run --rm -it spark-containerization:latest /opt/spark/bin/spark-submit /opt/spark/work-dir/spark_app.py
⚠️ Command Flag Breakdown

• --rm: Automatically deletes the temporary container filesystem upon exit to preserve disk space.

• -it: Attaches terminal interactive mode so Spark stdout streaming logs render directly in your console window.

  • Execute Docker Build & Run Commands Compile `spark-containerization:latest` image and run `spark-submit` inside the container.
