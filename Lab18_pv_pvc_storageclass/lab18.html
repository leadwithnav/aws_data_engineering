Module 1: Overview & Storage Concepts

Understand PersistentVolumes (PV), PersistentVolumeClaims (PVC), and Default StorageClasses (SC) in Kubernetes.

💡 Default StorageClass Binding
Instead of creating custom StorageClasses, Kubernetes clusters have a pre-configured Default StorageClass (e.g. standard (default) in Minikube, gp2 / gp3 in AWS EKS). When a PVC omits the storageClassName field, Kubernetes automatically binds it to the cluster's Default StorageClass!

Kubernetes Storage Abstraction Layer

Concept Abstraction Primary Function
StorageClass (SC) Provisioning Policy Pre-installed cluster policy. Enables Dynamic Provisioning of storage volumes.
PersistentVolumeClaim (PVC) Developer Storage Request Requests size (e.g. 1Gi). Omitting storageClassName uses the cluster default SC.
PersistentVolume (PV) Cluster Storage Resource Physical or cloud storage (AWS EBS, HostPath) dynamically created when a PVC is applied.

Module 2: Check Existing StorageClasses & Deploy PVC

Inspect pre-existing cluster StorageClasses and deploy PostgreSQL using the cluster default StorageClass.

2.1 Inspect Existing Cluster StorageClasses

Bash / PowerShell
# Inspect existing storage classes in your cluster
kubectl get storageclass

2.2 PostgreSQL PVC & Deployment Manifest (manifests/postgres-pvc-deployment.yaml)

YAML — postgres-pvc-deployment.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 1Gi
  # Omit storageClassName to use cluster default StorageClass
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: postgres-db
spec:
  replicas: 1
  selector:
    matchLabels: { app: postgres }
  template:
    metadata:
      labels: { app: postgres }
    spec:
      containers:
        - name: postgres
          image: postgres:15-alpine
          env:
            - name: POSTGRES_DB
              value: "ecommerce_db"
            - name: PGDATA
              value: "/var/lib/postgresql/data/pgdata"
          volumeMounts:
            - name: postgres-persistent-storage
              mountPath: /var/lib/postgresql/data
      volumes:
        - name: postgres-persistent-storage
          persistentVolumeClaim:
            claimName: postgres-pvc

2.3 Deployment Execution Commands

Bash / PowerShell
# 1. Apply postgres deployment & PVC
kubectl apply -f manifests/postgres-pvc-deployment.yaml

# 2. Verify PVC bound status & running pod
kubectl get pvc
kubectl get pods -l app=postgres

Module 3: Insert Records into PostgreSQL

Connect to PostgreSQL via `kubectl exec` and populate `orders` table inside `ecommerce_db`.

Bash / Zsh

POD_NAME=$(kubectl get pods -l app=postgres -o jsonpath='{.items[0].metadata.name}')

# 2. Connect via psql and insert orders data
kubectl exec -it $POD_NAME -- psql -U postgres -d ecommerce_db -c "

Module 4: Delete Pod & Verify Data Persistence

Delete the PostgreSQL pod and verify data survival in the newly recreated replacement pod.

🔥 Resilience Test
Delete the pod running PostgreSQL. The Kubernetes Deployment controller will immediately spin up a replacement pod and re-attach the existing PVC (`postgres-pvc`).
Bash / Zsh
# 1. Delete running PostgreSQL pod
kubectl delete pod -l app=postgres

# 2. Watch new pod spin up
kubectl get pods -l app=postgres -w

# 3. Get replacement pod name
NEW_POD_NAME=$(kubectl get pods -l app=postgres -o jsonpath='{.items[0].metadata.name}')

# 4. Query orders table in new pod — Data is 100% Intact!
kubectl exec -it $NEW_POD_NAME -- psql -U postgres -d ecommerce_db -c "SELECT * FROM orders;"

Module 5: Why & How to Use PVs with Apache Spark

Learn why Persistent Volumes are critical for Spark Shuffle Spill, Event Logs, and Streaming Checkpoints.

⚡ Spark & PV Integration Strategy
In Apache Spark on Kubernetes & EMR on EKS, mounting PVCs solves 4 enterprise challenges:

4 Primary Spark PV Use Cases

  1. Spark Shuffle Spill (spark.local.dir): When Spark shuffle datasets exceed executor container RAM during large joins/aggregations, Spark spills data to disk. Mounting fast NVMe/SSD PVCs (`/tmp/spark-local-dir`) prevents Executor Out-Of-Memory (OOM) crashes.
  2. Spark Event Logs (spark.eventLog.dir): Spark Driver pods write JSON event logs to a shared PVC. The Spark History Server mounts the same PVC to render post-execution DAG visualizations.
  3. Structured Streaming Checkpointing (checkpointLocation): PySpark Structured Streaming writes offset metadata and state store checkpoints to a PVC, ensuring streaming queries recover seamlessly upon driver restarts.
  4. Shared Datasets & ML Artifacts: Mounting pre-loaded PVCs read-only across executor pods avoids downloading multi-gigabyte reference datasets over the network.

Module 6: Spark PVC Pod Template Manifest

Examine Spark Driver Pod Template configuring volume mounts for shuffle spill and event logs.

YAML — manifests/spark-pvc-pod-template.yaml
apiVersion: v1
kind: Pod
metadata:
  name: spark-driver-pvc-template
  labels:
    app.kubernetes.io/component: driver
spec:
  containers:
    - name: spark-kubernetes-driver
      env:
        - name: SPARK_LOCAL_DIRS
          value: "/tmp/spark-local-dir"
        - name: SPARK_EVENTLOG_DIR
          value: "file:///tmp/spark-events"
      volumeMounts:
        - name: spark-shuffle-spill-volume
          mountPath: /tmp/spark-local-dir
        - name: spark-eventlog-volume
          mountPath: /tmp/spark-events
  volumes:
    - name: spark-shuffle-spill-volume
      persistentVolumeClaim:
        claimName: spark-shuffle-pvc
    - name: spark-eventlog-volume
      persistentVolumeClaim:
        claimName: spark-history-pvc
