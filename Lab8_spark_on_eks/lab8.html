Module 1: Overview & Prerequisites

Deploying PySpark Workloads on Pre-Existing Amazon EKS & Elastic Container Registry (ECR).

💡 Pre-Provisioned AWS Infrastructure

Your Amazon EKS cluster and Amazon ECR repository are pre-created by your instructor. You will connect to the existing cluster via aws eks update-kubeconfig and publish images to your designated ECR repository URL—no cluster creation (eksctl create cluster) required!

☁️ AWS CloudShell & Docker Workflow Note

AWS CloudShell environment does not run a background Docker daemon (docker build is run on your local machine or image is pre-pushed to ECR). Once the image is inside Amazon ECR, you can run 100% of Kubernetes submission & monitoring commands (kubectl, spark-submit) directly inside AWS CloudShell without local tools!

In AWS CloudShell, your session is pre-authenticated with your IAM credentials automatically! You do NOT need to run aws configure.

AWS CloudShell

aws sts get-caller-identity

2. Connect kubectl to Existing EKS Cluster & Check Cluster Status

Update your local kubeconfig file to connect to the pre-existing EKS cluster provided by your instructor and verify its active status:

PowerShell
# 1. Connect local kubectl to pre-existing EKS cluster
aws eks update-kubeconfig --name spark-eks-cluster --region us-west-2

# 2. Check EKS Cluster lifecycle status (Expected output: ACTIVE)
aws eks describe-cluster --name spark-eks-cluster --region us-west-2 --query "cluster.status" --output text

Module 3: Authenticate & Push to ECR

Publishing container images to the pre-existing Amazon ECR repository.

1. Configure ECR Environment Variables

Set your AWS region and ECR Registry URL. Note: Replace 786461327180.dkr.ecr.us-west-2.amazonaws.com with your own ECR Registry URL provided by your instructor or AWS Account:

PowerShell
$env:AWS_REGION = "us-west-2"
# Replace REGISTRY_URL with your own ECR Registry URL
$env:REGISTRY_URL = "786461327180.dkr.ecr.$env:AWS_REGION.amazonaws.com"
$env:ECR_IMAGE = "$env:REGISTRY_URL/spark-on-eks:latest"
Terminal
export AWS_REGION="us-west-2"
# Replace REGISTRY_URL with your own ECR Registry URL
export REGISTRY_URL="786461327180.dkr.ecr.$AWS_REGION.amazonaws.com"
export ECR_IMAGE="$REGISTRY_URL/spark-on-eks:latest"
AWS CloudShell
export AWS_REGION="us-west-2"
# Replace REGISTRY_URL with your own ECR Registry URL
export REGISTRY_URL="786461327180.dkr.ecr.$AWS_REGION.amazonaws.com"
export ECR_IMAGE="$REGISTRY_URL/spark-on-eks:latest"

2. Authenticate Docker with Amazon ECR

PowerShell
aws ecr get-login-password --region $env:AWS_REGION | docker login --username AWS --password-stdin $env:REGISTRY_URL
Terminal
aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $REGISTRY_URL
AWS CloudShell
aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $REGISTRY_URL

3. Tag & Push Image to Existing ECR Repository

PowerShell
docker tag spark-on-eks:latest $env:ECR_IMAGE
docker push $env:ECR_IMAGE
Terminal
docker tag spark-on-eks:latest $ECR_IMAGE
docker push $ECR_IMAGE
AWS CloudShell
docker tag spark-on-eks:latest $ECR_IMAGE
docker push $ECR_IMAGE
  • Authenticate & Push to ECR Authenticate Docker CLI with Amazon ECR, tag image, and push container to pre-existing ECR repository.

Module 4: Apply RBAC & Namespace

Configuring Kubernetes RBAC permissions and session environment variables.

1. Environment Variable Cleanup

⚠️ Local Session Fixes

Ensure local terminal environment variables do not override cluster container Python executables:

unset PYSPARK_PYTHON
unset PYSPARK_DRIVER_PYTHON

2. Apply Kubernetes RBAC Permissions (`eks/spark-rbac.yaml`)

Apply the ServiceAccount and RoleBinding required for Spark Driver to create Executor pods:

Kubectl CLI

  • Apply RBAC Permissions Clean environment variables and apply `spark-rbac.yaml` to grant Spark Driver pod permissions.

Module 5: Submit & Monitor EKS Job

Extracting cluster API master endpoint and submitting cluster mode Spark jobs.

1. Verify & Configure Local Spark Environment

Before submitting, ensure SPARK_HOME and PATH are set properly to invoke standalone Spark binaries:

PowerShell
# 1. Set SPARK_HOME and prepend Spark bin directory to PATH
$env:SPARK_HOME = "C:\Tools\spark-3.5.1-bin-hadoop3"
$env:PATH = "$env:SPARK_HOME\bin;$env:PATH"

# 2. Verify spark-submit.cmd binary is accessible
spark-submit.cmd --version
Terminal
# 1. Set SPARK_HOME and prepend Spark bin directory to PATH
export SPARK_HOME="/usr/local/opt/apache-spark/libexec"
export PATH="$SPARK_HOME/bin:$PATH"

# 2. Verify spark-submit binary is accessible
spark-submit --version
AWS CloudShell
# 1. Download & extract Apache Spark in CloudShell (if not pre-installed)
curl -O https://archive.apache.org/dist/spark/spark-3.5.1/spark-3.5.1-bin-hadoop3.tgz
tar -xzf spark-3.5.1-bin-hadoop3.tgz
export SPARK_HOME="$HOME/spark-3.5.1-bin-hadoop3"
export PATH="$SPARK_HOME/bin:$PATH"

# 2. Verify spark-submit binary is accessible
spark-submit --version

3. Submit Spark Job to Amazon EKS (Minimum Resources)

PowerShell
spark-submit.cmd `
  --master "k8s://$env:K8S_MASTER" `
  --deploy-mode cluster `
  --name spark-on-eks-job `
  --conf "spark.kubernetes.container.image=$env:ECR_IMAGE" `
  --conf spark.kubernetes.authenticate.driver.serviceAccountName=spark `
  --conf spark.executor.instances=1 `
  --conf spark.driver.memory=512m `
  --conf spark.driver.cores=1 `
  --conf spark.executor.memory=512m `
  --conf spark.executor.cores=1 `
  --conf spark.kubernetes.driver.pod.name=spark-driver `
  --conf spark.kubernetes.driverEnv.PYSPARK_PYTHON=python3 `
  --conf spark.kubernetes.driverEnv.PYSPARK_DRIVER_PYTHON=python3 `
  --conf spark.executorEnv.PYSPARK_PYTHON=python3 `
  --conf spark.executorEnv.PYSPARK_DRIVER_PYTHON=python3 `
  local:///opt/spark/work-dir/spark_app.py `
  /opt/spark/work-dir/sample_data.csv
